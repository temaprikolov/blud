# @bludstarsbot

Запуск на сервере (Beget):

    cd bludstars_bot
    python3 -m venv venv && source venv/bin/activate
    pip install -r requirements.txt
    screen -S bludstars
    python main.py          # выйти из screen: Ctrl+A, D

Перед запуском: бот должен быть **администратором** канала https://t.me/BludVpn
(и любых других каналов обязательной подписки / заданий), иначе проверка подписки не работает.

Админ-панель: /admin или кнопка «🛠 Админ-панель» в меню (только для ADMIN_IDS из .env).
База — SQLite, файл `bot.db` рядом с ботом.

## Обновление с прошлой версии
Старую базу можно оставить: новая таблица `settings` создастся сама.
После замены файлов выполни `pip install -r requirements.txt` — цветные кнопки требуют aiogram ≥ 3.31.
Награды, суммы вывода и срок рассмотрения заявки меняются прямо в боте: /admin → ⚙️ Настройки.

## Вывод звёзд
Пользователь выбирает сумму → создаётся заявка с номером → всем админам из ADMIN_IDS приходит уведомление
(ник, ID, сумма) с кнопками «Закрыть заявку» / «Отклонить». При закрытии звёзды списываются с баланса в боте,
пользователь получает уведомление. Все заявки — в /admin → «💫 Заявки на вывод».
Админы должны хотя бы раз нажать /start у бота, иначе Telegram не даст боту написать им первым.

## Кулдаун заданий
Не больше 2 выполненных заданий в минуту на человека (скользящее окно 60 секунд, считается по базе, перезапуск не сбрасывает).
Лимит меняется в /admin → ⚙️ Настройки → «Лимит заданий в минуту».

## Чеки
/admin → «🧾 Чеки» → «Создать чек». Режимы: по количеству человек (сумма + число людей + сколько получит один) или по времени
(30м / 12ч / 2д, число людей не ограничено). Можно задать пароль и обязательную подписку на каналы (бот должен быть админом этих каналов).
После создания бот присылает готовый пост с кнопкой «Активировать чек» — его можно переслать в канал или опубликовать кнопкой «📣 В канал».
Активация идёт по ссылке t.me/<бот>?start=chk_КОД; звёзды зачисляются на баланс в боте.

## Каналы обязательной подписки
При добавлении канала (/admin → «📢 Каналы» → «Добавить канал») бот спрашивает, проверять ли подписку:
🔎 с проверкой — бот должен быть админом канала, он сам узнаёт, подписан ли человек;
⏳ без проверки — достаточно ссылки (@username, https://t.me/… или ссылка-приглашение): после «Я подписался» бот ждёт 10 секунд и пускает.
Подходит для каналов с заявками на вступление и там, где бота нельзя сделать админом. Прошедшим ожидание повторно не показывается.
Старая база обновляется сама (добавляются колонки check_enabled и is_link), существующие каналы остаются «с проверкой».
Кнопка «➕ Добавить канал или ссылку» сначала спрашивает, что добавить: 📢 канал (с проверкой или без) или 🔗 любую ссылку (сайт, бот, соцсеть) — ссылка всегда без проверки, после «Я подписался» бот ждёт 10 секунд.

## Спонсорские подписки (Traffy, PiarFlow и Axionna)
Ключи в `.env`: `TRAFFY_API_KEY` (pk_live_…), `PIARFLOW_API_TOKEN` (токен аккаунта; ключ бота бот получает сам) и `AXIONNA_API_KEY` (AX-…, @axionaapp → Интеграция (API) → API Ключ). Пустой ключ = сеть выключена.
На /start, при входе в «Заработать звёзды» и по кнопке «Проверить подписку» бот просит у сетей спонсоров, показывает их кнопками-ссылками,
после «Проверить» спрашивает у сетей, всё ли выполнено, и открывает доступ. Любая ошибка сети/API — человека пускаем.
Диагностика для админа: `/traffy` показывает, что вернула каждая сеть. Успешное прохождение кэшируется на час.

## Автоматические задания в «Заработать звёзды»
Когда собственные задания закончились (или их нет), «Выполнить задание» берёт задания у Traffy, PiarFlow и Axionna: человек подписывается/запускает по ссылке,
жмёт «Проверить», сеть подтверждает выполнение — и бот начисляет 0.49 ⭐ (с тем же кулдауном и реферальным счётчиком). Награду платит бот, деньги за подписку платят сети вам.
Каждое сетевое задание человек получает один раз; пропущенное не возвращается. Свои задания из админки показываются первыми.
Стена спонсоров при входе (/start) остаётся — там звёзды не начисляются, это ваш доход «за вход».

## Счётчик подписок у каналов
В админке у каждого канала/ссылки в скобках — сколько человек подписались или выполнили условие через бота. Для каналов с проверкой считается тот, кто был не подписан, когда увидел стену, и потом подписался;
для каналов без проверки и ссылок — те, кто нажал «Я подписался» и прошёл ожидание. Уже подписанные ранее и просто зашедшие в бота не считаются. Счёт начинается с момента обновления.

## Анти-спам / анти-фрод / авто-чистка при бане

- `antispam.py` — лимит действий: не больше 5 событий за 3 с и 40 в минуту; лишнее молча отбрасывается, за повторный флуд — мут (30 с → 2 мин → 10 мин → 30 мин) и очки фрода.
- `fraud.py` — очки подозрительности (таблица `fraud_events`): флуд, нет языка интерфейса, пачка рефералов за 10 минут, проверка задания быстрее 1.2 с, задания «ровно по таймеру», активность почти 24 часа подряд; Telegram Premium и «доверенный» снижают очки.
  `≥ 50` — реферальные награды и вывод замораживаются, админам приходит уведомление с кнопками «Забанить / Доверять»; `≥ 100` — автобан. Пороги — в `config.py` (`FRAUD_*`, `RATE_*`).
- `moderation.py` + `services.purge_user_data` — при ЛЮБОМ бане (из профиля или из заявки) автоматически: удаляются заявки на вывод в ожидании и отклонённые (и сообщения о них у админов), обнуляется баланс (запись `ban_wipe` в истории — можно вернуть вручную), отменяются активации чеков, чистятся отметки подписок, рефереру возвращается награда за этого друга. Закрытые (выплаченные) заявки остаются как бухгалтерия.
- Админка: `/fraud` — список подозрительных; в профиле пользователя — фрод-очки и причины, кнопка «🛡 Доверять».

## Журнал действий (actions.log)
Одна строка — одно действие: `время  id @username  ТИП  детали` (время московское). Файл лежит рядом с ботом, хранится до ~20 МБ.

Типы: `MSG` сообщение/команда, `CB` нажатие кнопки, `NEW` новый пользователь, `TASK_OK/TASK_NO/TASK_WAIT` задания,
`REF_PAY` награда за друга, `WD_REQ` заявка на вывод, `WD_DONE/WD_REJ/WD_ERR` закрытие/отклонение, `CHECK` чеки,
`BONUS/DEDUCT` ручные начисления/списания, `BAN/UNBAN`, `FLOOD/FRAUD` подозрительная активность,
`SLOW` обработка дольше 3 с, `ERR` ошибка обработчика, `NET` проблемы связи с Telegram, `SYS` запуск/перезапуск.

Админу в боте: `/log` (последние 1000 строк файлом), `/log 300`, `/log @username`, `/log 123456789`, `/log wd` (по типу).
Или с сервера: `tail -n 3000 /bots/blud/actions.log`. Содержимое обычных текстовых сообщений (например, пароли чеков) в журнал не пишется.
